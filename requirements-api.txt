# Runtime dependencies for the FastAPI backend (Dockerfile.api) only.
#
# This is a trimmed subset of requirements.txt: verified (grep across
# src/api, src/agents, src/utils, src/rag, src/evaluation, src/mcp_servers)
# that streamlit, matplotlib, seaborn, datasets, ragas, accelerate, and
# langchain-openai are never imported by anything the FastAPI app's import
# graph reaches — they're only used by the Streamlit dashboard
# (src/dashboard/, src/main.py) and the offline evaluation/ragas/ and
# fine_tuning/ scripts, neither of which ship in the API container.
# Keep this list in sync with requirements.txt when adding a new API-side
# dependency.
#
# nixtla IS imported by src/agents/forecast/agent.py (optional TimeGPT
# candidate model, tried inside a try/except and gracefully skipped/logged
# if unavailable — see EMBEDDING_MODEL_PATH-style fallbacks elsewhere in this
# codebase). It's a thin client for Nixtla's hosted TimeGPT API (no local
# model weights), so keeping it has negligible image-size impact. Requires
# NIXTLA_API_KEY set in the environment to actually reach the service —
# without it, TimeGPT still gracefully falls back to Prophet/SARIMAX.
#
# trulens-dashboard is deliberately excluded too: it transitively pulls in
# Streamlit, matplotlib, and Jupyter/JupyterLab/notebook (a huge chunk of
# image weight) purely to launch TruLens's own standalone dashboard UI. The
# API only calls get_session()/run_with_trulens() (trulens-core/-feedback/
# -providers-openai) — launch_dashboard() now lazy-imports trulens.dashboard
# so it's never even reachable from the API's import graph. If you actually
# need the TruLens dashboard, run it locally with the full requirements.txt.
#
# torch is intentionally NOT listed here — Dockerfile.api installs it
# separately from the PyTorch CPU-only wheel index first, since plain
# `pip install torch` on Linux pulls a CUDA-bundled wheel (+ nvidia-cublas/
# cudnn/etc, several GB) even though this service never touches a GPU.
